## Architectural direction

Use domain-owned records and explicit adapters to build a renderer-neutral scene. Camera, selection, visibility, animation, and explanation are view state. Operational state, fit/constraint results, identity, unit conversion, and evidence remain owned by their canonical product or shipment contract.

```text
Canonical product / shipment / facility records
                 |
       Explicit domain scene adapters
                 |
  Semantic instances + geometry + status + provenance
                 |
    SVG / orthographic 3D / perspective / export
                 |
        Per-case isolated review artifact
```

This is proposed architecture, not a new store or runtime. Existing product contracts must be migrated deliberately before a shared scene replaces any live implementation. Approved visuals can remain exploratory if their data or interaction prerequisites are unresolved.

## Proposed scene contract rules

The exploration may illustrate these rules through fixture records. They are not a new production schema until reviewed and implemented.

1. **Identity:** `entityId` identifies the canonical unit/asset/slot/evidence record; `instanceId` identifies its drawing instance. Never derive identity from display labels or painter index. Preserve barcode and shipment links as references.
2. **Geometry:** Declare world units, source frame, axis meanings, origin, handedness, and pivot. Carry effective dimensions and orientation. Keep bounds, true shape, conservative envelope, and decorative detail distinct.
3. **Containment:** Reference parent identity and parent-space transform. Retain container-as-asset and container-as-space. Detect impossible/cyclic parents before a future operational renderer uses them.
4. **State:** Keep canonical operational state and revision separate from view selection, camera, filters, explosions, and animation progress. Display proposed/reserved/verified states distinctly.
5. **Measures:** Every displayed measure has value or explicit unknown, units, source, as-of time/revision, and status. A fallback estimate requires its own name and visible provenance.
6. **Scale:** Physical scenes use declared physical scale. Routes declare geographic/schematic/time modes. Financial and trust scenes declare semantic encodings; unsupported relationships are hypotheses.
7. **Explanation:** An overlay references the source metric/constraint/evidence record and affected entities. Domain engines retain authority; the renderer presents their results.
8. **Fidelity:** State exact, simplified, illustrative, or schematic geometry per scene. Any cap/aggregation must show omitted counts and preserve totals for inspection.
9. **Interaction:** Commands identify an entity and intention. View commands are reversible. Product mutations require a product-owned handler and appropriate authorization, outside the isolated review prototype.
10. **Export:** Persist semantic identity, effective transform, units, and visible source revision. Include limitations. A successful file write is not external format validation.
11. **Failure:** Unknown/malformed geometry, unavailable source, no placements, zero values, stale measurements, context failure, and partial capture must remain visible and recoverable.
12. **Review:** A case revision maps to one fixture and visual artifact. Human per-ID approval is recorded explicitly. Creative approval does not select a production implementation.

## Migration proposal and stop conditions

If specific cases are later approved and integration separately authorized, first resolve D01-D09 and establish fixture oracles. Extract pure math/primitives/annotations before moving domain scene builders. Connect Warehouse to canonical state before presenting its alternate view as operational. Then introduce shared scene adapters/backends and migrate one consumer at a time with a clear rollback path. Preserve existing useful behavior and product-specific policies; retire duplicates only after consumer and parity evidence.

Stop dependent implementation when ownership is contested, source contracts change, a scene would need invented physical data, a visual revision lacks the required human decision, or the scope would enter product/external/Git mutation without authorization. Continue independent documentation and isolated review work when safe. No extraction, product migration, test run, or integration approval is claimed by this document.
